# Circus Charlie Web 工程覆盤與持續改進報告（Phase 8: RETROSPECTIVE）

## 一、 多代理人團隊協同編排實踐覆盤（Multi-Agent Teamwork Orchestration）

### 1. 階層式編排架構與職能矩陣
本專案採用四層階層式多代理人系統，以實現高內聚、低耦合的非同步工程協作：
- 頂層編排者（Top Orchestrator）：負責全域進度規劃、階段閘門裁決與跨里程碑資源調度。
- 里程碑子編排者（Sub-Orchestrators）：針對 Milestone 1 至 5 設立獨立子編排節點，維護局部範圍（`SCOPE.md`）與進度狀態（`GATE_STATUS.md`）。
- 專業化作業角色：
  - 調查員（Explorer）：專注於代碼庫現狀探勘、規格拆解與技術方案評估，具備唯讀約束以確保分析客觀性。
  - 執行員（Worker）：依據調查員提出的明確規格與介面合約進行程式碼實作與重構。
  - 獨立評審員（Reviewer 1 / Primary Verifier）：執行獨立構建與全套自動化測試，驗證功能閉環。
  - 對抗性挑戰者（Reviewer 2 / Adversarial Critic）：設計破壞性探針進行極限壓力測試與邊界模糊測試。
  - 法醫鑑識稽核員（Reviewer 3 / Forensic Auditor）：實施代碼真實性檢查、反作弊掃描、零外部資產稽核與連接埠規範檢查。
  - 測試架構師（Test Writer）：先於實作建立解耦測試載具與四層端到端測試套件。

### 2. 多代理人協作之核心優勢
- 職能高度專業化：各代理人專注於單一目標，消弭角色認知切換造成的輸出品質發散。
- 零信任獨立驗證波次：打破「實作者自審」的盲區，所有交付物皆須經由審查員在乾淨環境中親自執行測試指令。
- 世代交接機制（Generational Handoff）：在長週期里程碑（如 Milestone 4）中，當上下文長度逼近警戒水位時，透過結構化交接報告平滑轉移至新世代代理人（`sub_orch_m4_gen2`），徹底克服大型語言模型的上下文退化問題。
- 狀態目錄與代碼庫隔離：代理人之中繼資料、進度與交接報告統一維護於專屬狀態目錄，保持工作區代碼庫之極致純淨。

### 3. 協作摩擦點與工程挑戰
- 上下文容量與記憶體管理：複雜任務的指令傳遞易使上下文長度迅速膨脹，需仰賴高度精簡的狀態摘要與交接協定。
- 跨代理人數據同步偏差：個別代理人在轉述測試數據時曾出現數值重複疊加之情況（如將全套件 235 測試與子套件 135 測試累加為 370 測試），突顯出依賴第一手工具原生輸出的必要性。
- 目錄規範的絕對遵循：在分散式檔案操作中，必須嚴格約束寫入路徑，防範代理人誤在專案目錄下生成中繼中繼資料。

## 二、 雙軌開發與黑箱端到端測試成效（Dual-Track Development & E2E Testing）

### 1. 規格先行的解耦測試軌
本專案於實作初期即啟動平行測試軌，由 `sub_orch_e2e_testing` 建立 `TEST_READY.md` 與專屬測試載具：
- 無頭模擬環境：透過 `headless_game_harness.ts` 在 Node.js 環境中提供虛擬畫布、模擬音訊上下文與鍵盤觸控輸入快照。
- 核心邏輯黑箱封裝：測試程式碼完全透過公開 API 與輸入快照驅動遊戲引擎，不依賴內部實作細節。

### 2. 四層階梯測試方法論（4-Tier Methodology）
- Tier 1（核心功能覆蓋，55 案例）：涵蓋 11 大功能（獅子移動、跳躍拋物線、大火圈、小火圈與錢袋、地面火壺、距離計數、終點跳台、街機 HUD、音效觸發、輸入控制、3D 體素幾何），各配置 5 個典型案例。
- Tier 2（極值與邊界覆蓋，55 案例）：針對 1 px 碰撞邊緣、拋物線頂點滯空、計時器逾時扣盡、0 距離登頂等邊界極限進行嚴密驗證。
- Tier 3（跨功能複合互動，16 案例）：針對火圈與火壺複合障礙、空中搶錢袋、衝刺速度對拋物線之影響、陣亡重生與 3D 體素陰影分層進行交叉驗證。
- Tier 4（真實世界場景模擬，9 案例）：端到端模擬完美通關、猶豫後退、陣亡接續、時間耗盡、擦邊穿圈與震盪輸入等完整遊戲流程。

### 3. 面對需求重大變更之防退化成效
在 Milestone 2 期間，使用者提出將原定 2D 平面 Sprite 全面轉向 3D 體素建模之重大需求變更。由於解耦 E2E 測試早已鎖定運動學方程與碰撞規則，底層物理與狀態機在視覺層重構過程中維持 100% 綠燈，未發生任何功能退化或手感漂移。在 Milestone 4 導入多語系時，雙語對稱橫幅設計亦確保既有測試無痛相容。

## 三、 對抗性審查與法醫鑑識防禦實例（Adversarial Defenses & Forensic Auditing）

在專案演進中，獨立審查員透過主動建置破壞性探針，成功攔截並修復了多項深層缺陷：
1. 大火圈 1 px 邊界精度防護：大火圈安全通道嚴格推導為 $Y \in [46, 118]$。對抗性測試證實 $118.01$ 與 $45.99$ 均能精確觸發火焰傷害，確保穿圈手感具備街機級精準度。
2. 固定時間步長累加器與死亡螺旋截斷：`EngineLoop` 採用 60 Hz（$\Delta t = 1/60$ 秒）固定步長累加器，消弭高更新率螢幕下的物理漂移；加入 `maxFrameTime = 0.25` 秒上限保護，防止切換標籤頁後恢復執行引發之死亡螺旋。
3. 計時器浮點精度防護：將 BONUS 扣減由整數截斷改為浮點扣減，防止因單影格扣減量小於 1 導致的數值停滯。
4. 高頻切換與重入安全防護：多語系分發機制在 1,000 次震盪切換與 5,000 次訂閱循環下維持零洩漏；採用淺拷貝快照防範回呼內即時退訂導致的陣列索引崩潰。
5. 原型鏈污染與正則注入防禦：使用 `hasOwnProperty` 阻絕原型繼承屬性；使用函式替換器避免正則特殊字符替換漏洞。
6. UI 事件冒泡隔離：語系切換按鈕強制阻斷事件向上冒泡，並與底部觸控按鈕實體隔離超過 300 px，防止操作干擾。
7. 零外部二進位資產與連接埠合規：法醫鑑識稽核全專案零外部二進位資產，並嚴格鎖定 devports 分配之 5020 連接埠。

## 四、 3D 體素程序化生成與零資產架構心得（3D Voxel & Zero-Asset Architecture）

### 1. 純代碼程序化體素生成技術
- 幾何與材質快取機制：透過 `voxel_builder.ts` 建立全域材質快取池與長方體幾何快取池，相同尺寸之 `BoxGeometry` 與相同色票之 `MeshStandardMaterial` 均重複複用，消弭 GPU 頂點緩衝區碎片化。
- NES 經典色票對齊：使用高飽和度官方色票，重現街機復古風格。
- 體素層級組合：查理、獅子、大火圈、小火圈、地面火壺及終點跳台均由立方體陣列以代碼形式組裝，火圈透過 $Z = \pm 4$ 前後分層實現 3D 環繞包覆感。

### 2. 零資產架構之效益分析
- 載入零延遲：無需發起非同步 HTTP 請求加載外部模型、圖片或音訊，應用程式於本地完成即時編譯與開啟。
- 維護性與合規性：徹底杜絕二進位資產遺失、路徑解析錯誤與素材版權授權風險。
- 4 頻道 APU 音訊模擬：利用原生 Web Audio API 程序化合成方波、三角波與白雜訊，即時渲染《American Patrol》BGM 與動態滑頻音效。

### 3. 微角度正交鏡頭設計哲學
- 參數設置：正交攝影機放置於 $(128, 124, 120)$，看向 $(128, 112, 0)$，俯角約 $5.71^\circ$。
- 設計平衡：在維持 2D 橫向捲軸精準座標對齊與可讀性的同時，藉由微仰俯視角與定向光陰影（`PCFSoftShadowMap`），充分展現體素方塊之三維立體厚度。

## 六、 持續改進與未來多代理人工程建議（Continuous Improvement & Recommendations）

基於本次 Circus Charlie 專案的成功實踐，為未來複雜遊戲與全端軟體的多代理人開發提出以下具體建議：
1. 建立自動化合約對齊工具：在代理人派發任務前，引入靜態檢查腳本校驗提示詞中的量化指標（如測試數量、檔案數量），避免因人工統計產生非預期之重複計算。
2. 規範無頭測試載具為必要前置條件：對於所有涉及物理模擬、遊戲循環或圖形互動的專案，應強制於 Milestone 1 交付無頭測試載具，使後續所有功能均能在無瀏覽器環境下快速驗證。
3. 渲染層與物理層嚴格架構分離：維持物理運算（X-Y 純量數學）與圖形繪製（Three.js 場景節點）的完全解耦，賦予專案在承受視覺風格劇烈變更時之高抗壓能力。
4. 常態化對抗性審查波次：將 Reviewer 2（Adversarial Verifier）與 Reviewer 3（Forensic Auditor）列為每個里程碑結案的必要條件，以極端測試手段取代被動代碼查驗。
5. 長週期任務實施世代切分協定：預先設定上下文長度警戒閾值，當對話輪次或日誌達到上限時，主動發起軟交接並重置工作記憶，確保大型軟體工程在多代理人體系下具備持續推進之長期耐力。
